# T1.8 — Accessibility quick fixes

`[R]` · size **S** · **Status: done** (22 September 2026) · depends on T1.5

## Why

The T1.5 a11y gate shipped with a dated `KNOWN_VIOLATIONS` baseline excusing the
`button-name` violation on `/auth`, and several of the ticket's own defects sat
outside axe's reach (clickable `div`s, no skip link, status changes that were
only visible, not announced). This ticket fixes the listed defects **and deletes
the baseline**, so the gate now fails on every serious/critical violation with no
exemption.

## Do — what was built

1. **`/auth` sign-in form** (`src/pages/Auth.tsx`):
   - the code input has `autoComplete="one-time-code"` and `inputMode="numeric"`;
   - the email field has a real label (`Label htmlFor="auth-email"`, visually
     hidden), `autoComplete="email"` and `aria-invalid`/`aria-describedby` wired
     to the error;
   - the icon-only submit button has an accessible name
     (`aria-label="Send sign-in code"`) — this is the defect the baseline
     excused;
   - errors render in `role="alert"` regions (the assertion is announced), and a
     persistent `role="status" aria-live="polite"` region announces the async
     progress (`Sending…` / `Code sent…` / `Verifying…` / `Resending…`);
   - **focus management**: focus moves into the code field when the code step
     appears, back to the email field after a send error or "Use different
     email", and the code field is re-focused after a wrong code;
   - **resend with a countdown**: the old "Try again" link (which silently
     returned to step one) is replaced by a `Resend code` control disabled for
     30 s after every send, counting down in the button label; both forms carry
     `aria-busy`.
2. **The two clickable `div`s** the audit named:
   - `src/components/cms/PageEditor.tsx` — the block card was a `div` with
     `onClick`; selection is now a real `<button type="button" aria-pressed>`
     (an explicit control, reachable by keyboard), with the card kept as a
     non-interactive container so the row's icon buttons are not nested inside a
     button.
   - `src/components/build/BuildWorkspace.tsx` — the version-menu click-away
     layer is decorative (`aria-hidden`) and now has a documented keyboard
     equivalent: Escape closes the menu (the toggle Button already opens it).
3. **A skip link** (`src/components/SkipLink.tsx`, new): the first focusable
   element in the landing, auth and app-shell layouts, jumping to a
   `#main-content` landmark that Landing, Auth, AppShell and AppIndex now
   declare (`tabIndex={-1}`).
4. **`src/components/ui/input-otp.tsx`** forwards a ref to the underlying
   `OTPInput` so the Auth page can manage focus.
5. **The gate** (`tests/e2e/a11y.spec.ts`): `KNOWN_VIOLATIONS` and the whole
   allow-list mechanism are **deleted**. The gate now covers `/`, `/auth` and
   `/app` (a signed-out `/app` is redirected to the sign-in screen and axe runs
   on what renders), plus two keyboard tests — the skip link is the first Tab
   stop and moves focus to main content, and the sign-in form submits by
   keyboard alone.

## Known limitations recorded honestly

- **`/app` is asserted through its signed-out redirect.** The app shell is
  behind `RequireAuth` and a live OTP session is not available to the public
  gate, so the `/app` entry exercises the redirect to the sign-in screen. The
  two clickable-`div` fixes inside the authenticated editor are not reachable by
  this gate; they are covered by code review and the keyboard change itself.
- **`page-has-heading-one` and the authenticated shell remain out of scope.**
  The gate fails on serious/critical only (unchanged from T1.5); this ticket did
  not raise the bar or weaken it.
- **No new dependency and no change to `vite.config.ts`, `convex.json` or
  `src/convex/_generated/`.**
