# T1.7 — Complete the Phase 0 regression suite

`[N]` · size **S** · **Status: not started** · depends on T1.5

## Why

Every Phase 0 control is implemented in code but **not one of them has a test**.
That is the gap between "we fixed it" and "it cannot come back". Each test below
must be written so that it **fails against the pre-fix code** — check that by
reverting the fix locally, watching the test fail, then restoring it. A test that
passes against the broken code proves nothing.

## The twelve tests

| # | Test | Asserts | Fix it locks in |
|---|---|---|---|
| R1 | Anonymous cannot use the product | No anonymous provider; a new user has Base access only; a row with `isAnonymous: true` is rejected by every guarded function | T0.2 |
| R2 | Client cannot change plan | `changePlan` from a client throws; the stored plan is unchanged | T0.3 |
| R3 | AI and scraping actions require sign-in | All 17 listed actions reject an unauthenticated caller | T0.4 |
| R4 | AI actions load context server-side | Passing a fabricated snapshot has no effect on the result | T0.4 |
| R5 | `safeFetch` blocks internal targets | Loopback, private ranges, link-local/metadata, non-HTTPS, and a public URL that redirects to a private address | T0.5 |
| R6 | Cross-tenant write blocked | User B cannot create a collection in user A's project (`collections.create`) | T0.6 |
| R7 | HTML is sanitized | `<script>`, `onerror=`, `javascript:` payloads never execute in the page renderer or the draft preview | T0.7 |
| R8 | Fake connection refused | No client-callable function can write `connected` | T0.10 |
| R9 | Shopify sync is per project | The sync action cannot read a deployment-wide store | T0.9 |
| R10 | Deletion completeness | Deleting a project leaves no row in **any** project-scoped table (enumerate them from `schema.ts`, do not hard-code) and no credentials | T2.5 precursor |
| R11 | Secret scan | CI fails on a planted dummy secret | T0.1 |
| R12 | No platform calls | With platform variables unset, sign-in and the AI paths make no request to platform domains | T0.8 |

## Do

1. Write R1–R12 in the runner added by T1.5. R5 and R10 are pure unit tests; R1,
   R3, R6 and R8 are Convex function tests; R7 and R12 need a browser.
2. For R10, generate the table list from `schema.ts` so a new project-scoped table
   cannot be forgotten. That is the seed of the data registry in T2.5.
3. For R12, assert on the network layer (Playwright request interception), not on
   a code search.
4. Where a test needs a second tenant, create two real users; the whole point is
   the cross-tenant boundary.

## Acceptance

- All twelve run in CI and pass.
- Each was demonstrated failing against the pre-fix code, with the evidence
  recorded in the PR.
- R4 stays red until T0.4's remainder lands — if so, mark R4 `blocked` in
  `docs/tickets/README.md` rather than deleting it or weakening it.

## Proof to record in the PR

For each test: its name, the assertion, and the pre-fix failure output.
