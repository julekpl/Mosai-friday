# T1.7 — Complete the Phase 0 regression suite

`[N]` · size **S** · **Status: done** (22 September 2026) · depends on T1.5

## Why

Every Phase 0 control is implemented in code but **not one of them had a test**.
That is the gap between "we fixed it" and "it cannot come back". Each test below
is written so that it **fails against the pre-fix code** — checked by reverting
the fix locally, watching the test fail, then restoring it. A test that passes
against the broken code proves nothing.

## The twelve tests

| # | Test | Asserts | Fix it locks in |
|---|---|---|---|
| R1 | Anonymous cannot use the product | No anonymous provider; a new user has Base access only; a row with `isAnonymous: true` is rejected by every guarded function | T0.2 |
| R2 | Client cannot change plan | `changePlan` from a client throws; the stored plan is unchanged | T0.3 |
| R3 | AI and scraping actions require sign-in | All 17 listed actions reject an unauthenticated caller | T0.4 |
| R4 | AI actions load context server-side | Passing a fabricated snapshot has no effect on the result | T0.4 |
| R5 | `safeFetch` blocks internal targets | Loopback, private ranges, link-local/metadata, non-HTTPS, and a public URL that redirects to a private address | T0.5 |
| R6 | Cross-tenant write blocked | User B cannot create a collection in user A's project (`collections.create`) | T0.6 |
| R7 | HTML is sanitized | `<script>`, `onerror=`, `javascript:` payloads never execute in the page renderer or the draft preview | T0.7 |
| R8 | Fake connection refused | No client-callable function can write `connected` | T0.10 |
| R9 | Shopify sync is per project | The sync action cannot read a deployment-wide store | T0.9 |
| R10 | Deletion completeness | Deleting a project leaves no row in **any** project-scoped table (enumerate them from `schema.ts`, do not hard-code) and no credentials | T2.5 precursor |
| R11 | Secret scan | CI fails on a planted dummy secret | T0.1 |
| R12 | No platform calls | With platform variables unset, sign-in and the AI paths make no request to platform domains | T0.8 |

## Do — what was built

1. **R1–R12 in the T1.5 runner.** Unit (Vitest + `convex-test`):
   `tests/unit/phase0-regressions.test.ts` (R1, R2, R3, R4, R6, R8, R9),
   `tests/unit/safe-fetch.test.ts` (R5, pure, hermetic),
   `tests/unit/deletion-completeness.test.ts` (R10),
   `tests/unit/secret-scan.test.ts` (R11, `@vitest-environment node`),
   `tests/unit/platform-detach.test.ts` (R12 identity half). Browser
   (Playwright): `tests/e2e/sanitized-html.spec.ts` (R7) and
   `tests/e2e/no-platform-calls.spec.ts` (R12 network half). Shared seeding is
   in `tests/unit/helpers.ts` (not a test file).
2. **R10 is generated from `schema.ts`.** The table list is derived at runtime —
   every table that declares a `projectId` field, plus `contentDocs` (project-derived
   through its parent piece). The fixture set must match that derived set exactly,
   so a new project-scoped table fails the test until it is covered. `oauthStates`
   is the one exemption and the test asserts *why* (no `by_project` index).
3. **R12 asserts on the network layer.** `no-platform-calls.spec.ts` inspects
   every request the browser makes on `/`, `/auth`, `/system` and a 404 route,
   and fails naming any that reaches a `freebuff.*` / `vly.*` host. The identity
   clause T0.8 completed ("tokens signed by the platform are rejected") is
   asserted against the live `auth.config.ts` object, not a source search.
4. **A test-only stub for the platform SDK.** `@vly-ai/integrations` reads
   `document` at import time and cannot load under `edge-runtime`, so
   `vitest.config.ts` aliases it to `tests/unit/stubs/vly-integrations.ts`. The
   stub records every `completion()` call, which is how R4 inspects the prompt the
   server actually built. No `src/` code is stubbed and no gate is weakened.
5. **Fixes the tests found.** Writing R10 exposed a real defect: the single
   cascade in `dal.ts` asked `buildVersions` for a `by_project` index the schema
   never declared, so **every** `projects.remove` / `billing.deleteAccount` threw.
   `dal.ts` now reaches `buildVersions` through its parent `build` (the same
   pattern as `buildMessages`).

## Known limitations recorded honestly

- **R4 is red by design.** It is written as `it.fails`, so the suite stays green
  and the gap stays visible. When T0.4 replaces the client snapshot with a
  server-loaded `projectId`, this test flips to a hard failure — the reminder to
  promote it to `it(...)`.
- **R12 covers the client and identity layers, not the server AI gateway.**
  T0.8 completed the identity detach and the browser makes no platform request;
  the server-side AI path still goes through the platform SDK
  (`@vly-ai/integrations`), which T2.9 (`ModelGateway`) retires. Recorded in
  `STATUS.md`.
- **R7 covers sanitize-on-render, not sanitize-on-save.** Server-side sanitization
  and the CSP are the T0.7 remainder.
- **The `e2e` suite starts its own dev server in CI.** Locally it reuses the
  platform's; while that server was unavailable during this ticket, the specs
  were verified with Playwright's own `webServer` (the CI path) and
  `VITE_CONVEX_URL` set to a format-valid placeholder, exactly as the workflow
  does.
