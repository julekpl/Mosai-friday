# T1.3 — Zero type errors

`[R]` · size **M** · **Status: done** · depends on T1.2

## Why

Type errors are the cheapest bug detector in this project and the platform blocks
every agent turn on them. They must be real, not masked.

## Current state (verified)

`bun convex dev --once && bun tsc -b --noEmit` exits **0** with codegen present.
So this ticket is not "fix 1,067 errors" — it is:

1. make the clean-clone case work (T1.2), and
2. keep the count at zero from then on.

Re-measure at the start of the work, after T1.2 lands, and record the number in
this file. If it is non-zero, fix the real causes.

**Re-measured for T1.3 (22 Sep 2026, post-T1.2): baseline = 0 errors, final = 0
errors.** No source change was required — T1.2's committed bindings removed the
only cause of the 1,067-error figure (it was a *pre-codegen* measurement, taken
while `src/convex/_generated` was git-ignored). What was left for this ticket was
to prove the count is real and not a silently-skipped check, and to record it.

## Do

1. Record the post-codegen error count as the baseline for this ticket.
2. Fix every error without `@ts-ignore`, `@ts-expect-error`, `as any`, or a
   weakened `tsconfig`. If a fix genuinely requires a cast, narrow it to a named
   type and explain it in a comment.
3. Where the error exposes a real bug (a nullable that is dereferenced, an action
   argument that is typed loosely), fix the bug, not the type.
4. Note that `dal.ts` deliberately uses a local `any` handle for the deletion
   cascade (it must be able to name any table in `schema.ts`). That is an accepted,
   documented exception with an eslint-disable; do not "fix" it by narrowing it
   into something that cannot see new tables.
