# T1.5 — Test tooling and CI

`[N]` · size **M** · **Status: not started** · depends on T1.1–T1.4

## Why

There are **no tests, no test runner and no CI** (verified: no test script in
`package.json`, no `.github/workflows`). Every Phase 0 fix is currently
"code in place, proof outstanding". This ticket turns the Phase 0 work into
something that cannot silently regress.

## Do

1. **Test framework.** Add Vitest with the Convex test harness for function-level
   tests (`convex-test` + `edge-runtime`), and Playwright for the browser journeys.
2. **Scripts** in `package.json`, using the manager chosen in T1.1:
   - `check` — typecheck + lint + unit tests + secret scan + the function audit
   - `test` — unit
   - `test:e2e` — Playwright
3. **CI workflow.** One job per concern so a failure names the cause:
   `install` (locked install, fails on lockfile drift) · `codegen` (T1.2's
   strategy, with the drift check) · `typecheck` · `lint` · `unit` · `security`
   (secret scan over history **and** the diff, dependency audit at high level,
   `bun run audit:functions`) · `e2e` (critical journeys, target under 20 minutes)
   · `a11y` (axe on the key pages).
   The full job list and its gates are in `docs/pack/06-test-strategy.md` §4.
4. **Wire the existing checks in, do not duplicate them.** `scripts/audit-public-functions.mjs`
   and `.gitleaks.toml` already exist — call them from CI.
5. **Stage the rollout honestly.** T1.7 supplies R1–R12; if the e2e job would fail
   because those tests do not exist yet, land the job with the tests that do exist
   and a single, dated TODO listing what is missing. Do not add a job that always
   fails, and do not mark it non-blocking permanently.

## Do not

- Add a coverage gate for generated or framework code.
- Add a full `vite build` to CI; the platform already typechecks, and a production
  build is not this ticket's job.

## Acceptance

- CI is green on the default branch.
- A deliberately broken commit fails **each** gate: a type error, a lint error, a
  failing unit test, a planted dummy secret, an unguarded public function, an axe
  violation. Prove each one — this is the whole point of the ticket.
- `bun run check` reproduces the same result locally.

## Proof to record in the PR

The workflow file path, one screenshot or log excerpt per gate, and the list of
gates with the commit that made each one fail on purpose.
