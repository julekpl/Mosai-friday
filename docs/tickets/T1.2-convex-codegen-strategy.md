# T1.2 — Convex codegen strategy

`[R]` · size **S** · **Status: done** · ⚑ decision required → **decided: Option A** (commit `src/convex/_generated`)

## Why

`src/convex/_generated` is git-ignored. On a machine that has never run Convex
codegen, every `_generated` import is unresolved and the resulting `implicit any`
cascades make type health impossible to judge — the pack measured **1,067 errors**
on a clean checkout, against **0 errors** once codegen has run. Any CI job that
typechecks must therefore generate or restore the folder first.

## Options

| Option | How | Trade-off |
|---|---|---|
| A. Commit `_generated` | Remove it from `.gitignore`, commit it, add a CI drift check | Typecheck works offline and in any CI; the generated code churns in diffs |
| B. Generate in CI | Run codegen against a dedicated CI deployment before typecheck | No committed artifacts; CI needs a deployment plus credentials, and local checkouts still need codegen |

## Decision (⚑ resolved 22 September 2026) — Option A

**Commit `src/convex/_generated` and add a drift check.** This is not a guess: it
is Convex's *current, documented* recommendation, and it is what T1.5's CI design
already assumes.

- Convex's own CLI help (`convex codegen --help`, run against `convex@1.46.0`):
  > "This code is generated automatically while running `npx convex dev` and
  > should be committed to the repo (your code won't typecheck without it!).
  > Regenerating it explicitly is rarely needed (e.g. in CI to ensure the correct
  > code was checked in). … This doesn't modify the code running on the
  > deployment."
- The Convex dev-workflow doc says the same (`docs.convex.dev/understanding/workflow`):
  > "Check in everything in your `convex/_generated/` directory. This ensures
  > that your code immediately type checks and runs without having to first run
  > `npx convex dev`. It's particularly useful when non-backend developers are
  > writing frontend code…"

Why not B: it fixes the *symptom* only in CI. A fresh clone on a developer
machine (or in the hosting platform's per-turn typecheck) would still fail until
codegen runs against a credentialed deployment, which is exactly the defect this
ticket exists to remove. A needs no credentials for ordinary typecheck; only the
drift job needs a deployment.

Alignment with T1.5: T1.5's `codegen` CI job is defined as "T1.2's strategy, with
the drift check". Under A that job regenerates with `convex codegen` and runs
`git diff --exit-code`; it needs `CONVEX_DEPLOYMENT` + `CONVEX_DEPLOY_KEY` in CI.
T1.5 composes the scripts below into `check` / the workflow — they are landed here
as `codegen` and `check:codegen` because T1.5 has not landed yet.

**Drift tool choice:** the drift check uses `convex codegen`, not `convex dev
--once` as the ticket's sketch suggested. `convex codegen` is the CLI's
purpose-built CI tool (per the help text above) and it does not push running code
to the deployment, so it is the safer of the two for a check that runs on every
PR.

## Do not

- Never hand-edit `src/convex/_generated/*` to fix a type error — that is a bug
  in the source, not the output. `AGENTS.md` §4 says so explicitly.
