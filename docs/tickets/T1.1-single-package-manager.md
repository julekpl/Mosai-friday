# T1.1 — One package manager, a consistent lockfile

`[R]` · size **S** · **Status: done** · ⚑ owner decision **made: bun** (22 Sep 2026)

## Why

A clean checkout cannot install. **Verified in the repository today:** both
`bun.lock` **and** `package-lock.json` are present, so two managers disagree about
the dependency graph. `package.json` also carries a peer conflict: Tiptap 3
packages (`@tiptap/react`, `@tiptap/starter-kit`, … all `^3.31.3`) sit next to
`@tiptap/extension-collaboration-cursor@^2.26.2`. Nothing downstream (tests, CI,
typecheck on a fresh clone) can be trusted until this is fixed.

Note for the owner: the hosting platform runs **bun** (`bun convex dev --once`,
`bun tsc -b --noEmit`), while the blueprint's commands assume **npm**. Pick one.
Recommendation: **bun**, because that is what actually runs the project today;
update the blueprint's command references rather than fighting the platform.

## Do

1. Confirm the decision (⚑) and record it in `docs/pack/STATUS.md` §6.
2. Delete the unused lockfile. Do not keep both "for safety".
3. Regenerate the chosen lockfile from a clean `node_modules`.
4. Resolve the Tiptap conflict. `rg -n "collaboration-cursor" src/` to confirm the
   package is unused — `src` imports `@tiptap/extension-collaboration`, not the
   cursor extension — then either remove it or upgrade it to a Tiptap-3-compatible
   version. Do not leave a peer warning in place.
5. Pin the runtime: `engines` in `package.json` and a `.nvmrc`, matching whatever
   the Convex deployment and the platform use.
6. Update the Commands section of `AGENTS.md` if the decision changes it.

## Do not

- Change any dependency version beyond what the conflict requires. Upgrades are
  T1.6's job.
- Touch `vite.config.ts` or the Convex configuration.

## Acceptance

- A fresh clone installs with the chosen manager and exits 0.
- No peer-dependency warnings from that install.
- Only one lockfile exists; `.gitignore` does not ignore either one.
- The chosen manager is recorded in `STATUS.md` §6 and used consistently in
  `AGENTS.md`.
