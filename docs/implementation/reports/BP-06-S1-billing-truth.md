# BP-06/S1 — Stripe test catalog and period-end cancellation

**Status: implemented locally, provider verification and integration pending.** This report covers the customer billing slice on existing branch `codex/bp-06-admin-stats`; BP-06/S2–S3 and production billing are not complete.

The Billing screen now reads active recurring price amounts, currency, interval and product names from configured Stripe **test** price IDs. An absent or conflicting price is unavailable, rather than shown with a guessed amount. Checkout re-fetches the price and rejects a changed amount or an untrusted return URL before creating a session. The browser redirect grants no entitlement; verified Stripe webhook handling remains the paid-state authority. Unapproved promotion-code entry and static package claims were removed. The local self-serve plan switch is explicitly labeled as a no-charge demo.

The user-selected cancellation policy is **at the current billing period end**. The in-app action sends `cancel_at_period_end=true`, checks Stripe's returned subscription ID, period-end flag and eligible status, and records the confirmation without downgrading the entitlement. Multiple eligible subscriptions or more than 100 historical rows fail closed until BP-06/S2 defines the mapping. A hosted portal session is available only when its retrieved active test configuration explicitly disables cancellation or sets it to `at_period_end`; otherwise the UI states that it is unavailable. The configuration is checked at session creation, not assumed from a dashboard default. See [Stripe's subscription update](https://docs.stripe.com/api/subscriptions/update) and [portal configuration](https://docs.stripe.com/api/customer_portal/configurations/object) contracts.
